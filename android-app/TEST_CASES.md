# Android 测试用例

## 自动化

- URL-001：HTTPS 地址接受并移除末尾 `/`。
- URL-002：Release 规则仅允许预置官方主机使用 HTTP，并拒绝其他 HTTP 主机。
- URL-003：Debug 规则允许局域网 HTTP。
- URL-004：拒绝无协议、空值和含账号信息的 URL。
- URL-005：服务器健康检查地址应稳定拼接为 `/api/health`。
- BUILD-001：`test`、`lint`、`assembleDebug`、`assembleRelease` 全部通过。
- REMINDER-001：当天提醒时间未到时，下一次触发为当天指定时间。
- REMINDER-002：当天提醒时间已到或已过时，下一次触发为次日指定时间。
- REMINDER-003：非法小时或分钟必须被拒绝。

### 智能规划通知自动化

- PLAN-PROTOCOL-001：接受 `SYNC_STUDY_PLAN` v1 完整 envelope，并保留账号、计划、有效期、日期和任务字段。
- PLAN-PROTOCOL-002：接受 `CLEAR_STUDY_PLAN` v1，且必须包含非空账号标识。
- PLAN-PROTOCOL-003：拒绝空值、畸形 JSON、未知消息类型、未知协议版本、缺失账号或计划标识的同步消息。
- PLAN-PROTOCOL-004：只接受 `yyyy-MM-dd` 本地日期和合法 ISO 时间；拒绝不存在的日期、有效期早于生成时间以及计划日期超出有效期。
- PLAN-PROTOCOL-005：单份计划最多接收 7 天、21 项任务；非法题量、非法优先级、非正数分钟和超限数组不得进入调度层。
- PLAN-PROTOCOL-006：标题、目标、完成标准和板块字段须去除 HTML、换行外控制字符和不可见字符，并按协议上限截断，通知文案不得执行或展示注入内容。
- PLAN-SCHEDULE-001：未来日期在用户设置的每日提醒时间触发；未设置时使用 20:00。
- PLAN-SCHEDULE-002：当天提醒时间未到则按设置时间触发；若已过且当天尚未送达，则在首次同步、开机、应用升级、权限恢复或时间变化后约 60 秒补发，不补发更早日期。
- PLAN-SCHEDULE-003：跨月、跨年和 `Asia/Shanghai` 时区下，触发日期必须与计划的 `scheduledDate` 一致。
- PLAN-SCHEDULE-004：旧日期、超过 `expiresAt` 的日期和纯 `REST` 日期不生成通知。
- PLAN-SCHEDULE-005：同一天多个非休息任务只生成一条提醒，合计分钟数准确，任务顺序稳定且摘要长度受限。
- PLAN-SCHEDULE-006：系统时间或时区变化后重新计算尚未触发的本地时间，不补发已过期日期。
- PLAN-STATE-001：重复同步相同账号、相同计划和相同内容时保持幂等，不产生重复 PendingIntent 或通知。
- PLAN-STATE-002：相同账号同步新计划时取消旧计划全部未触发提醒，并以新计划替换；已经送达的记录按产品规则清理。
- PLAN-STATE-003：相同消息重复同步时保持幂等；同一 `planId` 的任务内容或顺序变化时根据内容指纹重排。
- PLAN-STATE-004：账号定向 `CLEAR` 只能清对应账号；同源 `ACTIVATE` 切换账号时清理前一账号计划；会话 401 的显式 `RESET` 清理当前来源提醒；不同来源不得互相清理。
- PLAN-STATE-005：固定每日提醒与智能规划提醒可独立关闭；重新开启智能规划提醒时只恢复仍在有效期内的任务。
- PLAN-STATE-006：设备重启、进程重建、修改系统时间或时区后，从持久化快照恢复且不重复安排。

## APK 人工验收

1. 首次安装应直接打开预置官方服务器，不要求手工输入地址。
2. 断网时显示可重试错误页，不出现系统 WebView 错误页面。
3. HTTPS 证书异常时必须阻止继续访问。
4. 登录后杀进程并重新启动，会话仍可恢复。
5. Android 返回键先回退网页历史，无历史时显示应用操作菜单。
6. 外部域名由系统浏览器打开，同源页面保留在 App 内。
7. 完成首页、专项、考试恢复与交卷、申论、学习计划、错题、收藏、统计和管理员题库流程。
8. 在 360、390、412 宽度及横屏验证无阻断；网页自身问题参见根目录《网页移动端修改.md》。
9. 网页加载后不得显示额外原生标题栏，只保留网页自身移动端头部。
10. 更换服务器时必须显示独立设置页；非法地址、断网、健康检查非 2xx 均不得保存。
11. 网页根页面按 Android 返回键时应提供刷新、更换服务器、清除会话和退出入口。
12. Release 包默认访问 `https://8.163.38.217` 并拒绝保存任何 HTTP 地址；从 1.2.0 升级时自动把旧官方 HTTP 地址迁移为 HTTPS。
13. 软键盘弹出时页面使用 `adjustResize`，登录、注册和训练配置输入框不得被键盘遮挡。
14. 主页面 HTTP 4xx/5xx、WebView 渲染进程退出和不支持的外部协议均需显示可理解的恢复提示。
15. 长按网页和根页面返回菜单均可进入“备考通知”。
16. 设置页展示智能规划同步状态、待提醒日期、统一提醒时间，并分别提供智能规划与固定每日提醒开关。
17. 关闭智能规划提醒后只取消计划通知；关闭固定提醒后不影响计划通知；两个开关均关闭时不得再出现备考通知。
18. Android 13+ 首次开启须请求通知权限；拒绝权限不崩溃，并可跳转系统通知设置。
19. 通知点击后应复用或打开知政公考主界面，通知自动消失。
20. 重启设备、修改时区或修改系统时间后，已启用提醒应按新的本地时间重新安排。
21. 登录后生成智能规划，App 应显示已同步状态；在应用菜单中能看到当前计划、提醒时间和未来提醒日期。
22. 同一天有多个任务时只出现一条系统通知，通知展示任务数、总用时和可辨识的任务摘要，点击后直接回到智能规划页面。
23. 当天 20:00 后生成含当天任务的计划，应在短延迟窗口内收到一次补发通知；退出 App 或杀进程后仍可触发。
24. 重新生成计划后，旧计划尚未触发的通知全部失效；反复刷新或重复打开计划页不得重复通知。
25. 退出账号或登录另一账号后，不得继续收到上一账号的计划内容；清除计划后待触发通知必须全部取消。
26. 休息日不发送训练提醒；过期计划、历史日期和空任务日期不得产生通知。
27. 通知权限拒绝、通知总开关关闭或应用处于省电模式时不得崩溃；恢复权限后只安排仍有效的提醒。
28. 在通知栏折叠和展开状态检查长标题、多任务及中文标点，内容不得包含 HTML 标签、脚本片段、不可见控制字符或被无限截断。

## APK 版本与升级验收

- 本次功能版本使用 `versionCode = 6`、`versionName = "1.3.1"`，包名保持 `cn.zhizheng.exam`，以便从 1.2.0/1.3.0 原位升级。
- 用 1.2.0 安装包建立登录会话和每日提醒，再覆盖安装新包；账号 Cookie、服务器地址和原提醒开关不得丢失。
- 新包首次读取旧版单日提醒设置时应完成兼容迁移；没有智能计划快照时不得凭空产生计划通知。
- Debug 与 Release 分别执行单元测试、Lint 和打包；最终交付 APK 应核对 `versionCode`、`versionName`、applicationId 和签名证书。
- 当前测试包使用调试证书；若改用长期 Release keystore，不得把密钥、别名或口令提交到仓库，并需记录后续升级所依赖的证书指纹。
